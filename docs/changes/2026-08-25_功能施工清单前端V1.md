# 2026-08-25 · 功能施工清单前端 V1

## 做了什么

新增项目中心独立页面 `/project/checklist`，把 2026-08-25 的全功能打勾清单变成可长期维护的 B612 施工清单，而不是继续依赖反复打印。当前命名约定：B612 指网站，LoveHouse 指未来 App。

V1 包含：

- 28 个功能分区的代码基线。
- `已完成 / 进行中 / 待施工 / 灵感 / 风险复核` 五种状态。
- 全局完成度和各状态数量统计。
- 关键词搜索与状态筛选。
- 分区折叠与每区完成数。
- 快速“完成/待施工”切换与完整状态下拉选择。
- 完成日期与备注。
- 在任意分区新增自定义需求，并允许删除自定义项。
- 首页第二屏增加 `Build` 入口。

## 为什么这样做

原 A4 打印表会随着 B612 / LoveHouse 新需求持续增长，需要反复重新打印。施工清单属于工程/项目状态，不应该复用生活 `/todo` 或写进生活记忆库，因此单独建立项目中心模块。

## 数据与持久化设计

V1 暂不新建数据库表，不修改 Supabase：

- 28 区基线来自 `projectChecklistService.js`。
- 用户对基线条目的状态、完成日期、备注只作为 override 保存到浏览器 `localStorage`。
- 用户新增条目作为 custom item 保存到同一 localStorage。
- 基线和用户 override 分离，所以以后代码新增基线需求时，不会覆盖已经手工维护的本地状态。

localStorage key：`b612.project-checklist.v1`。

当前限制：V1 的手工状态只在当前浏览器设备保存，尚未跨设备同步。后续确认界面与字段稳定后，再决定是否建立独立工程表；不得与生活 `todo` 表合并。
