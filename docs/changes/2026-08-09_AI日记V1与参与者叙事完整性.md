# AI 日记 V1 + 参与者叙事完整性

- 日期：2026-08-09
- 执行者：Codex
- 状态：已完成代码与本地验证，等待 Draft PR 审阅

## 做了什么

- 继续使用 `save_memory(memory_type=diary)`，没有增加 MCP 工具或平行日记系统。
- 日记创建时由 `MemoryService` 根据 fixed actor 写入 `author=gpt|claude`；客户端提交 `author` 会在 AccessPolicy 被拒绝。
- 日记修订不接受客户端 author；普通修订沿用原作者，转换为 diary 时也由服务端固定当前 actor。
- Dream 的所有可替换 Curator provider 都必须经过统一输出标准化；`derived_memory` / `shared_candidate` 不能产生 diary，只有对既有来源的 `revision_suggestion` 可以保留 diary 类型。
- House Rules revision 2 与 `save_memory` 工具说明补充第一人称 AI 日记和真实参与者原则。

## 为什么这样做

- AI 日记应是当前 AI 对自身经历、判断、感受与变化的记录，不应退化为对小婷的客服式观察报告，也不能替小婷写她的日记。
- 身份、作者、来源与类型属于可信边界，不能只靠提示词约定；叙述方式则保持自由，不使用关键词或正则审查正文。

## 修改文件

- `bridge/memory/accessPolicy.js`：拒绝客户端伪造 author。
- `bridge/memory/service.js`：fixed actor 注入 diary author，修订继承原作者。
- `bridge/memory/dream.js`：统一 Curator 输出边界与 Dream diary 硬限制。
- `bridge/memory/house-rules.v1.json`：参与者完整性与第一人称 AI 日记规则。
- `bridge/mcp/tools.js`：让失忆 AI 直接理解 diary 的使用方式。
- `bridge/**/*.test.js`：GPT/Claude 对称、author spoofing、Dream provider 绕过与文案测试。
- `supabase/tests/memory_runtime_phase3.sql`：验证 private diary author、revision 继承、Shared exact revision 快照。
- `docs/ARCHITECTURE_CURRENT.md`、`docs/06_待开发列表.md`：同步当前契约和进度。
