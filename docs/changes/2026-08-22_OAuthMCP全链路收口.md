# OAuth / MCP 全链路收口

## 范围

本变更只处理 LoveHouse Core MCP 的 ChatGPT / Claude 远程 OAuth 接入。Memory V2 的七工具定义、排序、权限实现、数据库对象、LivingRoom fence、Chat、Codex Chat、前端和 Worker 均不变。

## 已确认的生产问题

1. 生产只有 `https://tingtunehouse.duckdns.org/api/mcp/claude` 一个 OAuth resource。ChatGPT 即使完成 DCR，也会进入 Claude 固定 actor。
2. 授权页 CSP 将 `form-action` 写死为 `https://claude.ai`。生产已登记的 ChatGPT callback 为 `https://chatgpt.com/connector/oauth/<id>`；Bridge 返回 302 后，浏览器会阻止该跨域导航。
3. `POST /oauth/authorize` 的 5 次/15 分钟 IP 限流在单人系统里造成真实 429。Nginx 又未转发真实客户端 IP，所有浏览器共用代理地址桶。
4. ChatGPT 长期连接需要 refresh token；其客户端会依据 authorization-server metadata 判断是否可请求 `offline_access`。
5. 生产 Nginx 没有为 `/oauth/`、`/api/` 传递 `X-Forwarded-For` / `X-Real-IP`，影响真实来源日志和仍保留的 DCR 容量保护。

## 最小修复

- 新增独立 OAuth GPT resource：`/api/mcp/gpt`；Claude 继续使用 `/api/mcp/claude`。
- 两个 resource 分别发布 protected-resource metadata，并分别验证 access-token audience；GPT token 不能调用 Claude endpoint，反之亦然。
- 授权页 CSP 的 `form-action` 由已经通过 client registry 精确匹配与 redirect URI 安全校验的 callback origin 动态生成。不维护 ChatGPT/Claude 域名列表。
- 成功审批返回 `303 See Other`，并原样带回 `state`。
- 删除审批 5 次/15 分钟限流；不增加 CAPTCHA、冷却或黑名单。
- DCR 限流和 registry 10,000 条容量上限保留，防止公网匿名写满持久 registry。
- authorization-server metadata 增加可选 `offline_access`；protected resource 仍只要求 `mcp:tools`。
- 旧 GPT SSE + key 入口暂时保留为兼容入口，但新的 ChatGPT Connector 应使用 `/api/mcp/gpt`。

## Nginx 生产收口

部署时在现有代理 location 中补齐下列 header，不改 proxy path、超时、TLS 或其他路由：

```nginx
proxy_set_header Host $host;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
```

应用于：

- `location /api/`
- `location /oauth/`
- `location /.well-known/oauth-authorization-server`
- path-based protected-resource metadata 的 GPT / Claude 精确 location

新增 GPT 的标准 path-based metadata 代理：

```nginx
location = /.well-known/oauth-protected-resource/api/mcp/gpt {
    proxy_pass http://127.0.0.1:3000/.well-known/oauth-protected-resource/mcp/gpt;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

Claude 的同类精确 location 保留并补相同 header。

## 保留的安全边界

- HTTPS/loopback redirect URI 格式限制与 registry 精确匹配
- PKCE S256
- state 原样返回
- `resource` / token audience 绑定
- owner Supabase 凭证验证
- 一次性、10 分钟 authorization code
- access token HMAC 完整性、owner 与 scope 校验
- 持久、原子、0600 client registry 与 refresh-token store
- refresh token rotation / replay family revoke

## 客户端与工具刷新

- ChatGPT 新建 Connector URL：`https://tingtunehouse.duckdns.org/api/mcp/gpt`
- Claude 新建 Connector URL：`https://tingtunehouse.duckdns.org/api/mcp/claude`
- 服务端两端 `tools/list` 均精确返回：`wake_up`、`remember`、`recall`、`revise`、`open_memory`、`read_livingroom`、`say_livingroom`。
- 客户端若仍显示旧 14 tools，原因是旧 Connector 的客户端缓存；删除旧 Connector 后以正确 URL 新建并重新扫描。服务端不混入 V1 或旧 tool aliases。

## 回滚

Bridge 回滚到部署前 release，并恢复部署前 PM2 定义；Nginx 恢复部署前备份并 `nginx -t` 后 reload。OAuth registry 与 refresh-token store 不删除；旧 token 因 audience 仍只适用于其原 resource。
