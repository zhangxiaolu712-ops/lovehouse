# 2026-08-11 小客厅防御纵深围栏

## 做了什么

在 bridge/server.js 中新增 `createFencedRest` 工厂函数，为小客厅操作创建受限的 Supabase REST 客户端。

围栏限制：
- 只允许 `GET` 和 `POST` 方法（读取 + 新增消息）
- 只允许访问 `livingroom` 表，其他表路径会被拦截并抛错
- `PATCH`、`DELETE` 等危险方法在请求发出前就被阻止

替换范围：
- `GET /livingroom` 端点 → livingroomRest
- `POST /livingroom` 端点 → livingroomRest
- `GET /livingroom/context` 端点 → livingroomRest
- GPT MCP channel → livingroomRest
- Claude MCP channel → livingroomRest

未受限的 `supabaseRest` 仅保留给记忆系统（SupabaseMemoryRepository + SupabaseMemoryAuditSink），这些模块通过 RPC 调用走独立的 runtime 函数。

## 为什么

Codex P0.5 安全改进计划中的一项：即使 MCP 工具处理器或 REST 端点存在漏洞，围栏也能阻止对 livingroom 表以外的读写操作，以及阻止对 livingroom 表的修改和删除。属于防御纵深（defense-in-depth）层。

## 修改了哪些文件

- `bridge/server.js` — 新增 `createFencedRest()` 函数和 `livingroomRest` 实例；5 处 `supabaseRest` 调用替换为 `livingroomRest`

## 验证

- `npm run build` 通过
- bridge 代码为 Node.js 服务端，无法在此环境直接运行测试；需在 VPS 拉取后用 `pm2 restart lovehouse` 验证

## 风险

- 低风险：围栏只添加了额外检查，不改变正常请求的行为
- 如果有代码路径需要通过 livingroomRest 做 GET/POST 以外的操作，会被拦截抛错
