- 执行者：Codex
- 状态：本地实现与验证完成，等待复审；未部署生产

## 做了什么

- 新增服务端 `OAuthClientRegistry`，将动态注册生成的 OAuth client 从进程内 `Map` 移到独立文件仓库。
- 保存 `client_id`、redirect URIs、grant/response types、application type、token endpoint auth method、`created_at`、`expires_at`、`revoked_at` 与 client secret expiry。
- confidential client 的原始 secret 仍只在 DCR 响应中返回一次；仓库只保存以 `OAUTH_TOKEN_SECRET` 计算的 HMAC 摘要。
- client registry 使用 0700 私有目录、0600 状态文件、同目录文件锁、临时文件 fsync、原子 rename 与目录 fsync。
- 授权页、授权提交、authorization-code exchange 和 refresh 均从 registry 读取 active client；未知、过期、撤销、redirect 不匹配或 registry 损坏继续 fail closed。
- 保留原有 `response_type=code`、PKCE S256、resource/audience、scope 与 token auth method 校验，没有放宽 OAuth 边界。

## 风险与下一步

- registry 是单 VPS runtime state，不是跨主机分布式存储；VPS 迁移需要停写后迁移该文件，或让客户端重新 DCR。
- OAuth runtime state 包含 `oauth-clients.json` 与 `oauth-refresh-tokens.json`。同机 release/PM2 切换必须保持服务账号、绝对路径与 `OAUTH_TOKEN_SECRET`；不得让部署清空 release 外的状态文件。
- VPS 搬迁必须停止旧 Bridge 写入后，以单写者方式迁移两个 0600 文件、0700 目录和相同 secret。不同 VPS 不能同时写本地副本；active-active 需要另开共享事务 store 工单。
- client registry 丢失时旧 client 与其 refresh 均 fail closed，重新 DCR + 人工授权；refresh store 丢失时旧 refresh fail closed，但未过期 access token仍按自身期限有效，可用保留的 client 重新授权；两个文件都丢失则重新 DCR + 授权。
- 损坏或权限错误返回 503，不自动覆盖状态；先停 Bridge 并恢复受控备份，无法恢复再按状态丢失流程处理。secret 轮换会使旧 access/refresh/confidential client digest 失效，需要重新 DCR/授权。
- 回滚到旧 Bridge 时保留两个文件；旧版本期间产生的内存 DCR 不会持久化，前滚后这部分客户端需重新注册。
- 提交 Draft PR 后等待复审；不在本工单部署生产或重试 OAuth。
