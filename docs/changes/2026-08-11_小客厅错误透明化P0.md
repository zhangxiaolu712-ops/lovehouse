# 2026-08-11 小客厅错误透明化 P0

## 做了什么

- 给 `createLivingroomRest` 增加不可由普通函数伪装的 fence 标记；MCP 工具只接受经过该 fence 的小客厅 REST 入口。
- fence 继续只允许 `livingroom` 的 GET 与 POST，并新增响应合约：读取必须返回行数组，单条写入必须返回唯一确认行。
- 将上游 401/错误对象转成显式异常，保留安全的状态与错误码信息，不再解释为空消息。
- 删除 MCP 和 Bridge 端点中的 `rows || []`、`(no messages yet)` 与 `{ ok: true }` 回退。
- 保留 GPT=`GPT`、Claude=`CC`、Owner=`小婷` 的服务端固定 sender；未改变认证协议或 Cloudflare→VPS 拓扑。

## 为什么

原 MCP 适配器在读取时把非数组或空值退化为 `[]` / `(no messages yet)`，写入时把缺少返回行退化为 `{ ok: true }`。这会把 Supabase 401、错误对象或未确认写入伪装成正常结果。P0 修复必须让失败显式可见，同时防止插件绕过 Bridge 的 livingroom fence 直接使用 Supabase REST。
