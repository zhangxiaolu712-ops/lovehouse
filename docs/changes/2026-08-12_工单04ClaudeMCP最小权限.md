## 范围

本工单只处理小客厅 #60，并遵守 #77 的最终边界：让 Bridge 的非交互 Claude CLI 显式加载 LoveHouse MCP，只能调用 LoveHouse 聊天/Memory 工具，MCP 加载失败时明确失败。没有修改 Gate B、Toy、Cloudflare→VPS 拓扑、Memory migration/开关、Supabase/RLS/anon 或生产服务。

- VPS 受控试验证明：Claude 2.1.218 会在 `system/init` 报告 `mcp_servers:[{name:"lovehouse",status:"failed"}]`，随后仍生成普通回答并以 `subtype:"success"` 退出。只检查退出码会把 MCP 失败吞成假成功。

审计仅输出参数、路径、版本、环境变量名和聚合状态；未输出任何密钥值、聊天正文或 Claude 认证材料。

## 实现

新增 `bridge/claudePolicy.js` 作为可测试的启动策略：

- MCP 只有一个：`lovehouse`，类型为 HTTPS HTTP MCP；URL 依次取 `CLAUDE_MCP_URL`、`MCP_RESOURCE_URL`、`OAUTH_BASE_URL + /api/mcp/claude`。URL 禁止明文 HTTP、userinfo、query 和 fragment，避免凭证进入 argv。
- `--tools ""` 关闭全部 Claude 内建工具；因此 Bash、Edit、Read、Write、Web 等默认不可用。
- `--permission-mode dontAsk` 配合显式 `--allowedTools`，只预先允许 13 个 `mcp__lovehouse__*` 工具；未来 Bridge 新增工具时，白名单与 adapter route 的一致性测试会先失败。
- `--strict-mcp-config` 只加载本轮内联的 LoveHouse MCP；`--setting-sources "" --settings "{}"` 隔离 user/project/local settings，`--disable-slash-commands` 关闭 skills/slash commands。
- 明确禁止且未使用 `--dangerously-skip-permissions`。
- Claude 子进程不再继承完整 PM2 环境。只保留 HOME、PATH、locale、TERM/TMP、用户/shell、XDG 路径和 `CLAUDE_CONFIG_DIR`；Supabase key、Livingroom key、OAuth signing secret、PM2 变量、Claude/API token 与代理变量均不传入。

脱敏后的实际启动形态：

```text
/usr/bin/claude -p <message> \
  --output-format stream-json --include-partial-messages --verbose \
  --system-prompt <redacted> \
  --tools "" \
  --allowedTools <13 个 mcp__lovehouse__* 固定工具名> \
  --permission-mode dontAsk \
  --disable-slash-commands \
  --setting-sources "" --settings "{}" \
  --strict-mcp-config \
  --mcp-config '{"mcpServers":{"lovehouse":{"type":"http","url":"https://<redacted>/api/mcp/claude"}}}' \
  (--session-id <server-uuid> | --resume <server-uuid>)
```

### MCP 初始化硬门

Bridge 在每次 `--session-id` 和 `--resume` 启动后检查第一个 `system/init`：

1. 必须报告名为 `lovehouse` 的 MCP；
2. status 必须为 `connected`；
3. `tools` 必须与 13 项白名单精确相等；
4. init 缺失、状态失败或工具漂移时终止进程并通过 SSE 明确报错；
5. 门禁通过前不转发 text/thinking，避免失败后生成的普通回答泄露为假成功。

## 验证

- Claude 策略与 session 定向测试：17/17 通过。
- Bridge 全量测试：128/128 通过。
- VPS Claude 2.1.218 失败旁路：MCP `failed` 但 CLI 普通回答/exit success 的行为已复现，Bridge 单测确认不会转发该假回答。
- VPS 最小环境旁路：使用清空环境后仅 HOME/PATH/LANG/USER/LOGNAME/SHELL，Claude 仍以现有服务端认证成功回答；证明无需把 Bridge/Supabase/PM2 secrets 传入子进程。
- VPS localhost 临时 MCP 旁路：首轮得到 `system/init connected`，随后出现真实 `tool_use → tool_result → continued answer`；同一 UUID `--resume` 后再次 `connected`，工具再次成功调用。临时服务只监听 `127.0.0.1`，结束即退出；没有部署或重启生产 Bridge。
- 前端 lint 通过（仅仓库既有 warnings）；production build 通过（仅既有大 chunk 提示）；`git diff --check` 通过。

## 风险与回滚

- 部署前必须先完成服务器侧 Claude MCP OAuth 授权/凭证存储；缺失或失效会明确阻断 `/chat`，不会静默退化成无工具聊天。
