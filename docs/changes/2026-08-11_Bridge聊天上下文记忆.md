# 2026-08-11 Bridge 聊天上下文记忆

## 做了什么

VPS bridge 的聊天端点从"每轮失忆"升级为"最近30条上下文"。

新增 `bridge/chatContext.js` 独立模块：
- `addMessage(role, content)` — 存消息到内存，超过30条自动淘汰最旧的，单条上限2000字
- `buildPrompt(message)` — 把最近的对话历史拼成 `[最近的对话]...[现在]` 格式，传给 `claude -p`
- `clear()` — 清空历史（清除对话或新会话时调用）
- `getStats()` — 返回当前消息数和上限（预留给以后 UI 展示）

server.js 改动：
- `/chat` 端点：收到消息后用 `buildPrompt` 拼上下文，收到回复后用 `addMessage` 存入历史
- `newSession=true` 时先 `clear()` 再开始新对话
- `/reset` 端点：同步清空上下文历史
- 流式回复过程中同时收集完整回复文本，结束后存入历史

## 为什么

之前 bridge 用 `claude -p` 每轮都是全新进程，小克完全没有上下文记忆。现在拼入最近30条对话，小克能接续之前的话题，同时上下文长度封顶，不会越聊越贵。

## 设计决策

- **内存存储**：bridge 重启会清空历史，可接受（重启不频繁，且不丢失重要数据）
- **30条封顶**：约几千 token，走订阅额度开销很小
- **单条2000字截断**：防止单条超长消息吃掉过多上下文预算
- **独立模块**：小婷说以后可能换更好的方案，chatContext.js 可以整个替换

## 修改了哪些文件

- `bridge/chatContext.js` — 新文件，上下文管理模块
- `bridge/server.js` — 导入 chatContext，改写 /chat 和 /reset 端点
